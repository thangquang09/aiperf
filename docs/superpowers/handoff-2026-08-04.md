## Key facts / gotchas
- **AIPerf uses `dag_jsonl` as a "format barrier"** — the converter builds
  the JSONL; the engine runs upstream code unchanged. Minimal merge risk.
- **Concurrency is session-based, not request-based**: each lane picks 1
  session, runs turns sequentially, then picks a new session. ccu=1 on a
  61-turn agentic session = lane occupied for ~15 min.
- **Run-starvation**: pool 500 chat + 100 rag + 19 agentic. Short runs
  under-sample agentic because chat sessions cycle fast. Fix options:
  raise ccu (8-10) or duration (600-900s), or cut `num_traces` to 1-2.
- **Tokenizer**: `z-ai/glm-5.2` is NOT on HuggingFace. Use
  `--tokenizer zai-org/GLM-5.2` (the upstream repo) for client-side
  tokenization, or `--use-server-token-count` to skip. 75.7% token-count
  discrepancy between client tokenizer and server when using client.
- **Cache hit metric**: comes from gateway-reported
  `usage_prompt_cache_read_tokens` in the `usage` field of the API
  response (SGLang prefix cache). For accurate %, divide by
  `usage_prompt_tokens` (server ISL), not client ISL.
- **Production mix reference** (Vercel AI Gateway research): agentic =
  22% req / 59% tokens; chat = 78% req / 41% tokens. Token-weighted axis
  is the right one for KV-cache/cost pressure.
- **Weka "256k"** = per-request ISL cap at 256k (drops >256k), NOT a
  256k-token request. Context accumulates: turn0~660 tok, turn1~64k (tool
  output), turn2+ small delta + 85-99% prefix-cache hit.
